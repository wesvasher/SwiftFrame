# SwiftFrame

Native macOS (27+) SwiftUI app for stop motion animation. A document-based app: every open `.swiftframe` project is its own capture window (live camera + onion skin, review a frame, real-time playback, filmstrip editing). Public repo, licensed under PolyForm Noncommercial 1.0.0 with an added permission to make any animation (see LICENSE).

## Workflow
- All coding is done from Claude Code; Xcode only builds in the background.
- The Xcode project is generated by XcodeGen from `project.yml`. Never hand-edit or commit `SwiftFrame.xcodeproj`. New Swift files under `SwiftFrame/` are picked up on the next `xcodegen generate`.
- `scripts/build.sh` builds Debug and launches the app. `--no-open` builds without launching.
- `scripts/test.sh` runs the unit tests (Swift Testing, `SwiftFrameTests/`). CI runs them on every push.
- `scripts/make-dmg.sh [version]` builds Release into `dist/SwiftFrame-<version>.dmg`.
- Scripts set `DEVELOPER_DIR` to /Applications/Xcode.app, so `xcode-select` doesn't need changing.
- Local builds are signed by `Config/Local.xcconfig` (gitignored). On this Mac it uses the self-signed "CardStock Local Signing" certificate (shared with CardStock; `scripts/make-signing-cert.sh` makes one elsewhere) with hardened runtime off. A stable signature keeps camera access across rebuilds. Don't override `CODE_SIGN_IDENTITY` on the command line.
- GitHub Actions uses the `xcode-27` runner label (images are keyed by Xcode version, not macOS).

## Releases
- Bump `MARKETING_VERSION` in `project.yml`, commit, then tag `vX.Y.Z` and push the tag. `.github/workflows/release.yml` builds the DMG and creates the GitHub Release, with the tagged commit's message (minus the co-author line) as the notes, so write release commit messages for readers.
- Builds are ad-hoc signed (not notarized) until a Developer ID is set up.

## Code layout
- `SwiftFrame/App`: `SwiftFrameApp` (a `DocumentGroup`; `AppDelegate` opens a new window at launch instead of the Open panel), `SettingsView` lives in `Views/` (Settings scene: General, flash on capture; Appearance, Auto/Light/Dark `AppAppearance` applied to `NSApp.appearance` at launch and on change, with SwiftCut's `ChoiceCards`), `FrameCommands` (the Frame menu, acting on the key window's model through `@FocusedObject`; Space plays/pauses, and pausing leaves the playing frame selected so Play resumes from it), and `WindowModel`: one per window, owning the camera, the decoded-image cache, the selection, the viewer mode (`live`, `review`, `playback`), capture, edits, import and export. Every edit goes through `WindowModel.edit` → `StopMotionDocument.edit`, which registers undo (and so marks the document dirty).
- `SwiftFrame/Document`: `Project` (Project.json: frames, frame rate, onion skin, mirror, loop, last camera, optional `crop`), `FrameCrop` (a shape by its size at 1080 lines, e.g. a6600 1620×1080; `rect(sourceWidth:sourceHeight:)` is the biggest centered rect of that shape, so exact pixels at 1080p and scaled for other signals; `ciRect` for Core Image; presets in `FrameCrop.presets`; applied to new captures in `captureStill(mirrored:crop:)`, to focus peaking, and to the live preview, where `CameraPreview` clips its layer to the zoomed crop so cropped frames and the onion skin line up) and `Frame` (id, image id, hold). Frames point at images by id, so duplicates share a picture. The frame-list edits (remove, duplicate, move, reverse, hold, playback indexing) are pure `[Frame]` extensions covered by `FrameListTests`. `StopMotionDocument` is a `ReferenceFileDocument` package: `Project.json` + `Frames/<uuid>.jpg`; saving writes only images frames use and reuses the existing file wrappers for unchanged pictures.
- `SwiftFrame/Camera`: `CameraController` (one `AVCaptureSession` per window on its own queue; device discovery and hot-plug; the newest pixel buffer kept for `captureStill`; focus peaking pictures worked out on the camera queue about 15 times a second while the live view asks, published on its own `PeakingFeed` so they don't redraw the window), `ShutterRemote` (app-wide, `.shared`: fires a Sony camera's shutter over Bluetooth LE with each capture, after the HDMI picture is taken, via the RMT-P1BT remote protocol in `SonyRemote` (service 8000FF00-…, write FF01: half press 0107, full 0109, release 0108, 0106; FF02 status, subscribing triggers pairing); unofficial, from community reverse engineering; Bluetooth isn't touched until "Fire Camera Shutter" is on in the inspector; remembers the paired camera and reconnects; entitlement `device.bluetooth`), `FocusPeaking` (on, color, sensitivity 1–10 with named `Preset`s, in UserDefaults; the sidebar has − number + and a presets menu; `overlay(for:)`: downscale, gray, median (noise), `CIEdges`, threshold, dilate, tinted mask) and `CameraPreview` (`AVCaptureVideoPreviewLayer` in a flipped container, aspect-fit so the onion skin lines up; zoom and pan set its layer frame exactly as `scaleEffect` + `offset` would).
- `SwiftFrame/Views`: `CaptureWindow` (no left sidebar: the viewer, capture bar (`CameraSelector` menu at the left beside the summary; no frame rate control here (it's in the inspector's Playback section: a menu of common rates and a 1–60 stepper, no text field because Space/Delete are window shortcuts); then timeline zoom buttons (there is no viewer mode switch: the Capture tile, ⌘L, Space and clicking frames change modes): `WindowModel.thumbnailWidth`, width only, height fixed, steps in `thumbnailWidths`; new projects start at `standardThumbnailWidth` (84, 4:3 at the 63-point height), opened ones at the last step chosen; plus Zoom to Fit (⇧Z) from `FilmstripLayout.fitWidth` and the measured `filmstripVisibleWidth`; below `compactWidth` padding and gaps shrink to a sixth of the width and the grip and hold badge hide, so fit widths can go down to half a point) and filmstrip; right `.inspector` `FrameInspector` (`Views/Sidebars.swift`): an `InspectorPanel` of folding `InspectorSection`s (`Views/InspectorPanel.swift`, copied from SwiftCut; folded state per title in `@AppStorage`; here a section's accessory, its on/off switch, shows even when folded): Frame, Selection or Project, then Camera (camera, mirror, crop via `CropPicker`, which shows what it keeps of the camera's `videoSize`), Camera Shutter (`CameraShutterSection`), Focus Peaking (color, `PeakingSensitivity`: − number + and a presets menu), Onion Skin, Playback; the footer has Duplicate/Reverse/Delete for the selection; shown state in `@SceneStorage`; `WindowKeyMonitor` (a local event monitor on the capture window) plays/pauses on Space wherever focus is (the sidebar list or a focused button would otherwise take it; skipped while a text field is typed in, and it swallows the event so the menu's Space doesn't fire too) and captures a frame when ⌘ is tapped alone (⌘ down then up with no key, other modifier, click or scroll between), since menus can't use a lone modifier; toolbar: camera menu, focus peaking (⇧⌘P), Play Full Screen (⌘F; `WindowModel.isPlayingFullScreen`: plays from the start in a `ViewerView(isFullScreen:)` overlay over the whole window with the toolbar hidden, `FullScreenWindow` puts the window in and out of full screen and ends it if the user leaves full screen; ⌘F again or Escape ends it, paused), onion skin toggle (`WindowModel.showsOnionSkin`, ⇧⌘O: the plain live camera or the Capture view with the onion skin; not saved in the project; going live when switched), loop, export (onion skin settings are in the inspector)), `ViewerView` (live + onion skin + focus peaking, review, `TimelineView` playback honoring holds; zoom 1–8× from `WindowModel.viewerZoom`/`viewerPan` (pan clamped to the view), via the corner `ViewerZoomControls`, ⌥⌘= / ⌥⌘− / ⌥⌘0, pinch, double-click, drag to pan; pictures use `.zoomed(model)`, the camera preview zooms its own layer), `FilmstripView` (when zoomed in past the visible width, SwiftCut's `StripNavigator` (copied into `Views/StripNavigator.swift`, without its Zoom to Fit button since the capture bar has one) sits above the strip (its space is always kept, empty when not zoomed in, so the layout doesn't jump) with a `NavigatorOverview` of the frames; scrolling uses `ScrollPosition` + `onScrollGeometryChange`, and the visible range excludes the pinned Capture tile; `FilmstripContent` is the frames, the `EndSpace` (`FilmstripLayout.endSpaceWidth`, exactly what the tile covers) and the overlays; a scrub strip above the frames and a SwiftCut-style `Playhead`: thin and faint, thicker on hover or drag, gliding evenly from one frame's middle to the next over that frame's time on screen while playing (`WindowModel.playbackPosition(at:)`, in an unpaused `TimelineView` made fresh when playback starts, since a paused one may not restart), centered on the frame otherwise; while playing, `FireTrail` (`Views/FireTrail.swift`: a `Canvas` particle system, sparks kept in strip coordinates in `FireTrail.Sparks`, drawn only in a `reach`-wide window behind the line, additive in dark mode, darker embers in light mode, reset on a loop or restart) streams fire behind it only with Habanero Mode on (Settings › General › Playback, `GeneralSettings.habaneroModeKey`, off by default) and Reduce Motion off; positions come from `FilmstripLayout` since every cell is the same width; scrubbing past the last frame goes live; the `CaptureTile` is an overlay pinned to the ScrollView's trailing edge on a `.bar` background, with an `EndSpace` exactly its width ending the frames so the last frame scrolls clear of it; clicking it goes live, or captures when live; the live playhead sits in the gap after the last frame; cells have no number, just a `GripHandle` under the thumbnail (grab pointer; the whole cell drags); the right-click menu `FrameMenuItems` acts on the selection or the clicked frame: Copy Picture, Save Picture As…, Duplicate, Hold, Reverse, Move to Start/End, Insert Pictures Before…, Delete; selection, context menu, drag to reorder via `FrameDrag`, drop picture files via `FrameDrop`).
- `SwiftFrame/Export`: ⌘E or the toolbar opens `ExportSheet` (`Views/ExportSheet.swift`), set up by `ExportSettings` (kind movie/GIF/images, codec, .mov/.mp4 (ProRes forces .mov), picture format, size cap by height, GIF loop; saved as JSON in UserDefaults), then a save panel (a new folder for images). `MovieExporter`: AVAssetWriter (H.264, HEVC, ProRes 422 Proxy/LT/422/HQ/4444); each frame lasts `hold` ticks at a timescale of the frame rate. `ImageExporter`: animated GIF via ImageIO (delays rounded at each frame's end, in hundredths, so the total stays on time) and image sequences (`frame_0001.png`…, one file per frame of playback, so holds repeat). Still on `AVAssetWriterInputPixelBufferAdaptor`, which macOS 27 deprecates (the only build warnings). `MovieExporterTests`.
- `SwiftFrame/Support/FrameImages`: `ImageCoding` (JPEG encode/decode/import) and the per-window `NSCache` of full images and thumbnails.
- `SwiftFrame/Resources`: asset catalog (accent color) and `AppIcon.icon` (Icon Composer; the layer PNG is drawn by code, edit it in Icon Composer).
- Sandboxed: user-selected files read/write, camera and Bluetooth.

# SwiftFrame

Native macOS (27+) SwiftUI app for stop motion animation. A document-based app: every open `.swiftframe` project is its own capture window (live camera + onion skin, review a frame, real-time playback, filmstrip editing). Public repo, licensed under PolyForm Noncommercial 1.0.0 with an added permission to make any animation (see LICENSE).

## Workflow
- All coding is done from Claude Code; Xcode only builds in the background.
- The Xcode project is generated by XcodeGen from `project.yml`. Never hand-edit or commit `SwiftFrame.xcodeproj`. New Swift files under `SwiftFrame/` are picked up on the next `xcodegen generate`.
- `scripts/build.sh` builds Debug and launches the app. `--no-open` builds without launching.
- `scripts/test.sh` runs the unit tests (Swift Testing, `SwiftFrameTests/`). CI runs them on every push.
- `scripts/make-dmg.sh [version]` builds Release into `dist/SwiftFrame-<version>.dmg`.
- Scripts set `DEVELOPER_DIR` to /Applications/Xcode.app, so `xcode-select` doesn't need changing.
- Local builds are signed by `Config/Local.xcconfig` (gitignored). On this Mac it uses the self-signed "CardStock Local Signing" certificate (shared with CardStock; `scripts/make-signing-cert.sh` makes one elsewhere) with hardened runtime off. A stable signature keeps camera access across rebuilds. Don't override `CODE_SIGN_IDENTITY` on the command line.
- GitHub Actions uses the `xcode-27` runner label (images are keyed by Xcode version, not macOS).

## Releases
- Bump `MARKETING_VERSION` in `project.yml`, commit, then tag `vX.Y.Z` and push the tag. `.github/workflows/release.yml` builds the DMG and creates the GitHub Release, with the tagged commit's message (minus the co-author line) as the notes, so write release commit messages for readers.
- Builds are ad-hoc signed (not notarized) until a Developer ID is set up.

## Code layout
- `SwiftFrame/App`: `SwiftFrameApp` (a `DocumentGroup`; `AppDelegate` opens a new window at launch instead of the Open panel), `SettingsView` lives in `Views/` (Settings scene: General, flash on capture; Appearance, Auto/Light/Dark `AppAppearance` applied to `NSApp.appearance` at launch and on change, with SwiftCut's `ChoiceCards`), `FrameCommands` (the Frame menu, acting on the key window's model through `@FocusedObject`; Space plays/pauses, and pausing leaves the playing frame selected so Play resumes from it), and `WindowModel`: one per window, owning the camera, the decoded-image cache, the selection, the viewer mode (`live`, `review`, `playback`), capture, edits, import and export. Every edit goes through `WindowModel.edit` → `StopMotionDocument.edit`, which registers undo (and so marks the document dirty).
- `SwiftFrame/Document`: `Project` (Project.json: frames, frame rate, onion skin, mirror, loop, last camera) and `Frame` (id, image id, hold). Frames point at images by id, so duplicates share a picture. The frame-list edits (remove, duplicate, move, reverse, hold, playback indexing) are pure `[Frame]` extensions covered by `FrameListTests`. `StopMotionDocument` is a `ReferenceFileDocument` package: `Project.json` + `Frames/<uuid>.jpg`; saving writes only images frames use and reuses the existing file wrappers for unchanged pictures.
- `SwiftFrame/Camera`: `CameraController` (one `AVCaptureSession` per window on its own queue; device discovery and hot-plug; the newest pixel buffer kept for `captureStill`) and `CameraPreview` (`AVCaptureVideoPreviewLayer`, aspect-fit so the onion skin lines up).
- `SwiftFrame/Views`: `CaptureWindow` (a `NavigationSplitView`: left sidebar `CaptureSidebar` (camera list, mirror, onion skin, frame rate, loop); detail is the viewer, capture bar (`FrameRateSwitch`: a small Liquid Glass 12/24/Custom capsule, Custom opens a 1–60 fps popover with no text field because Space/Delete are window shortcuts, last custom rate in `@AppStorage`; Live/Frame/Play switch, then timeline zoom buttons: `WindowModel.thumbnailWidth`, width only, height fixed) and filmstrip; right `.inspector` `FrameInspector` (selected frame or frames: preview, position, start time, hold, actions; project summary when nothing is selected), shown state in `@SceneStorage`; `CommandTapMonitor` captures a frame when ⌘ is tapped alone (a local event monitor: ⌘ down then up with no key, other modifier, click or scroll between), since menus can't use a lone modifier; toolbar: camera menu, loop, play, export (frame rate and onion skin are only in the left sidebar); both in `Views/Sidebars.swift`), `ViewerView` (live + onion skin, review, `TimelineView` playback honoring holds), `FilmstripView` (a scrub strip above the frames and a SwiftCut-style `Playhead`: thin and faint, thicker on hover or drag, gliding through frames while playing via `WindowModel.playbackPosition(at:)`, centered on the frame otherwise; positions come from `FilmstripLayout` since every cell is the same width; scrubbing past the last frame goes live; cells have no number, just a `GripHandle` under the thumbnail (grab pointer; the whole cell drags); the right-click menu `FrameMenuItems` acts on the selection or the clicked frame: Copy Picture, Save Picture As…, Duplicate, Hold, Reverse, Move to Start/End, Insert Pictures Before…, Delete; selection, context menu, drag to reorder via `FrameDrag`, drop picture files via `FrameDrop`).
- `SwiftFrame/Export/MovieExporter`: AVAssetWriter to .mov (H.264, HEVC, ProRes 422); each frame lasts `hold` ticks at a timescale of the frame rate. Still on `AVAssetWriterInputPixelBufferAdaptor`, which macOS 27 deprecates (the only build warnings). `MovieExporterTests`.
- `SwiftFrame/Support/FrameImages`: `ImageCoding` (JPEG encode/decode/import) and the per-window `NSCache` of full images and thumbnails.
- `SwiftFrame/Resources`: asset catalog (accent color) and `AppIcon.icon` (Icon Composer; the layer PNG is drawn by code, edit it in Icon Composer).
- Sandboxed: user-selected files read/write and camera.
